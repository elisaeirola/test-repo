
# Reflection

This was the first time I had attempted to create a website. Prior to this course, I had no experience with coding or programming so I felt out of my depth at the beginning of the process. Over the semester, I started to understand the basics and was able to visualise how I might create a website. I did need some time to play around with and test various features of the code. For instance, it took me some time to determine exactly what I had to write in order to integrate a markdown file into the website. Considering this was a core component of our assignment, it was important for me to learn how to achieve this and understand why the end result worked.

Another part of the process that required time and patience to complete was the CSS styling of the page. While I understood the basics, such as how to choose a font and background colour after learning about those in class, it took time to determine the specifics. For instance, establishing the size ratio between headings, regular text and images required some trial and error. Ultimately, I landed on stylings that I was happy with.

By far, the most challenging part of creating the website for me was the integration of an API. After the lectures, I understood what an API was and what its function was, so I assumed it would not be too complicated to add one to my page. However, once I set out to code the final product, the API turned out to be the feature I most struggled to get to function properly. For whatever reason, most of the APIs I initially tried to include would not deploy correctly to the final webpage.

As this was all new to me, it is certainly possible that I had written a part of the code incorrectly, and that was why the APIs would not function correctly. I tried multiple different APIs, but each one seemed to cause issues in one way or another. Initially, I wanted to incorporate an API that was linked to heritage, but I could not find one that suited my needs. I then decided to try an advice or joke API, but these would not deploy correctly. The advice API did not deploy to the web page at all, even after several attempts. Meanwhile, I had no luck with various joke-themed APIs either. The joke API that worked the best only deployed occasionally and would often result in an “undefined” error on the web page.

While this may have been due to my own inexperience with website creation, or problems out of my control, I did not want to use an inconsistent or dysfunctional API. Therefore, I had to sort through various APIs until I found one that was stable and worked consistently. The fox image API I chose was the best option, and I attempted to integrate it into the content of the web page as fluidly as possible. Once the issue with the API had been sorted, the rest of the process was much smoother sailing.

While the CSS styling was time-consuming, it was rewarding to see the page morph into something more pleasant to look at. In addition to colour and font choices, it was also interesting to consider how to display the information I wanted to include. As I am more familiar with writing essays, it was a new challenge to determine how to lay out the information in a more website-friendly manner. As the medium is different, I wanted to make sure the page was not too text-heavy.

I wanted to present relevant, informative text that was easy to read and not too dense. I thought it best to split up the text into different pages based on theme. Incorporating the button function was particularly useful here. The buttons made it easier to present the information in shorter, more digestible sections, rather than in one long piece of text. I started with a general overview of heritage management and the different types of heritage. I then moved onto the impact of digital technologies on heritage management, and introduced some practical examples of this. I wanted to highlight how digital technologies allow for more diverse and collaborative heritage-making processes.

Once I had written the pieces of text I wanted to include, I converted the word document into separate markdown files for each page. Once I had these files ready, I integrated them into the overall code for the website. I was not sure if I would be successful immediately as I had previously experienced some challenges during the creation process, but I was pleasantly surprised to find that it worked correctly on my first attempt. Once this was complete, I finalised the styling of the website and did a final overview making sure I had included everything I was supposed to.

Overall, I am happy with the website I was able to create. I had no prior experience in website creation or design, so being able to create a website at all was pleasantly surprising. While starting this process was daunting as it was something completely new to me, I wanted to challenge myself. I am happy I did, as the end result is something I can be proud of and could not have achieved even three months ago.
